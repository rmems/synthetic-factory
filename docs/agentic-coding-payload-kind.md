# Payload kinds in `rmems/agentic-coding-trajectories`

Tracked in [#74](https://github.com/rmems/synthetic-factory/issues/74)
(`PAYLOAD_KIND_MIXED`).

The published dataset advertises "19 raw **coding** records". It holds 19
records generated by the coding factory, but only **3** of them are coding
episodes a loader can read at the top level. The other **16** are thalamic
gate records that wrap a coding episode one level down, under
`executed_action`. This document is the read-only measurement behind that
claim, the exact card text an operator should publish, and the command that
re-derives every number here.

Nothing in this document rewrites a raw record and nothing here has been
uploaded to the Hub. The card write is an operator action; see
[Scope](#scope).

## Verdict

| Question | Answer |
|---|---|
| Is the payload kind mixed? | **Yes.** 3 `episode` records, 16 `thalamic` records. |
| Is the Dataset Viewer broken? | **No.** The `viewer` config indexes all 19 rows and is lossless against `data/raw/`. |
| Does the dataset need a declared union schema? | **No.** Declaring a default config over the mixed `data/raw/*.jsonl` would replace a projection that already works. |
| Is any record foreign to this factory? | **No.** All 19 are stamped `meta.factory = agentic-coding-trajectory-factory`. |
| Do any steps publish `decision_basis`? | **No.** 0 of 361 steps; all 361 publish the legacy `thought` field. |

Notes on that table.

- **The 3 episodes carry no top-level identifier.** They are addressable only
  as `episodes.jsonl:1..3`. Issue #74 lists 16 episode ids; all 16 belong to
  the *thalamic* records and live at `state.episode_id`. Nothing identifies the
  3 episodes but their source coordinate.
- **`episodes.jsonl` is a legacy payload filename.** It does not match the
  `batch-r*.jsonl` convention the other eight files follow, and it is the file
  a `batch-*` glob silently drops. It carries all 3 episode records.
- **All 16 gate records wrap a real coding episode.** `executed_action` is a
  full `goal` + `steps` object in every one of them, so the coding supervision
  is present in all 19 records — it is the *reachability* that differs.

Issue #74 reports "77/77 steps" publishing `thought` and no `decision_basis`.
That is right for the 3 top-level episodes. Counting the episodes wrapped
inside the 16 gate records, the real figure is **361 of 361**. The card's
"Planned curated release" section promises records "whose `decision_basis` is
grounded in visible plans, tool calls, observations, or reflections"; no record
in this release meets that bar, which is consistent with `training_ready:
false`.

## Where the existing reports were right and wrong

**Issue #74's split is correct.** "3 coding episodes + 16 thalamic-gate
records" is exactly what this scan reproduces, down to all sixteen
`act-rNN-00N` ids and the two supervisor families.

**A sibling scan reported 16, not 19.** An agent working
[#26](https://github.com/rmems/synthetic-factory/issues/26) reported that *all
16* published `agentic-coding-trajectory-factory` records are thalamic wrap
records whose `executed_action` embeds a coding episode. The per-record half of
that is right and this audit confirms it: all 16 gate records do wrap a real
coding episode. The **count** is not right — the corpus publishes 19 records,
not 16. The three it misses are in `data/raw/episodes.jsonl`, whose name does
not match `batch-r*.jsonl`. Any enumeration built on a `batch-*` glob reports
"16 of 16 thalamic" and never sees the episodes. (`episodes.jsonl` is a known
legacy round-1 payload name; `scripts/publish_grok46_hub.py` lists it in
`LEGACY_R1_NAMES` for exactly this reason.) The two reports are therefore
compatible: 16 wrap records is a true statement about the `batch-*` shards, and
19 records / 3 + 16 is the true statement about the release.

**Two smaller corrections to #74.** Its "77/77 steps" figure counts only the 3
top-level episodes; across the whole release the figure is 361 of
361. And the sixteen ids it lists under "Episode ids" are the ids of the
*thalamic* records, read from `state.episode_id`; the 3 actual coding episodes
carry no id at all.

## Reward and meta columns are not shared

The two shapes do not share a reward column. The 3 episodes carry `reward`
(`success`, `quality`, `cost`, `notes` on all three). The 16 gate records carry
`reward_components`, an open key-bag: **165 distinct keys** across 16 records,
of which only `total` appears on all 16 and **146 appear on exactly one
record**. `meta` also differs: the episodes carry `factory` / `run` / `round` /
`tags`; the gate records add `failure_modes_exercised` (16),
`gate_error_quadrant` (14), `distillation` (14), `distillation_notes` (2),
`gate_vindicated` (2), and `gate_error_class` (1).

This is why a single flat union schema over `data/raw/*.jsonl` would be a poor
trade even if the viewer were broken: it would have to declare `reward`,
`reward_components`, and `meta` as opaque JSON columns and would still leave
half of every row null.

## What is not broken

The Dataset Viewer is healthy and must be left alone.

- The card declares one config, `viewer`, over `data/viewer/records.parquet`
  with columns `source_file`, `source_line`, `record_json`.
- The datasets-server indexes **19 rows** in `viewer/train`.
- Those rows cover every raw file, including `episodes.jsonl`
  (3 rows), and every `record_json` decodes to exactly the
  raw record at its `source_file:source_line`.

So #74 is not a viewer-indexing problem, and the fix must not add a default
config over `data/raw/*.jsonl`. The correct fix is card prose.

## Card text to publish

Insert this section into the dataset card, after "Published raw payload".
It is stored verbatim as `card_disclosure.markdown` in
`docs/agentic-coding-payload-kind.json`.

```markdown
## Payload kinds in this release

The 19 published records are **not** 19 top-level coding episodes. They are two
record shapes, both stamped `meta.factory = agentic-coding-trajectory-factory`:

- **3 coding episodes** — `goal` / `steps` / `outcome` / `reward` / `meta` — all in
  `data/raw/episodes.jsonl`. These records carry no top-level identifier; address
  them as `episodes.jsonl:1`, `episodes.jsonl:2`, `episodes.jsonl:3`.
- **16 thalamic gate records** — `state` / `proposed_action` / `safety_decision` /
  `executed_action` / `future_outcome` / `reward_components` / `meta` — two per file
  across `data/raw/batch-r02.jsonl` through `data/raw/batch-r09.jsonl`. Record ids
  `act-r02-001`, `act-r02-002`, `act-r03-001`, `act-r03-002`, `act-r04-001`,
  `act-r04-002`, `act-r05-001`, `act-r05-002`, `act-r06-001`, `act-r06-002`,
  `act-r07-001`, `act-r07-002`, `act-r08-001`, `act-r08-002`, `act-r09-001`,
  `act-r09-002`. Supervisors: `thalamic-relay-gate-v2.4` on 8 records and six
  `thalamic-gate.*` deployment variants on the other 8. Gate decisions: 10 MODIFY,
  3 ACCEPT, 3 REJECT.

Every one of the 16 gate records embeds a complete coding episode under
`executed_action` (`goal` + `steps`), so coding supervision is present in all 19
records — but in 16 of them it sits one level down, behind a safety-gate decision
that shaped it. **A loader that expects a top-level `goal` / `steps` object reaches
3 of 19 records, not 19.** Read the wrapped episodes at
`record["executed_action"]`.

Counting the wrapped episodes, the release holds 361 agent steps: 77 in the 3
top-level episodes and 284 inside the 16 gate records.

**No step in this release publishes `decision_basis`.** All 361 steps publish the
legacy `thought` field, plus `reflection`. This release is therefore not a source
of observable-basis coding supervision; that remains the pending curated release
described below.

Two further consequences of the mix. `reward` (on the 3 episodes) and
`reward_components` (on the 16 gate records) are different columns, and
`reward_components` is an open key-bag: 165 distinct keys across the 16 records, of
which only `total` appears on all 16 and 146 appear on exactly one record. `meta`
likewise varies — the 3 episodes
carry `factory` / `run` / `round` / `tags`, while the gate records add
`failure_modes_exercised`, `gate_error_quadrant`, `distillation`, and other keys on
subsets.

The Dataset Viewer projection (config `viewer`, over `data/viewer/records.parquet`)
is complete and lossless for all 19 records, including the 3 in the legacy-named
`episodes.jsonl`. It is not affected by this disclosure and must not be replaced by
a default config over the mixed `data/raw/*.jsonl`.
```

## Re-deriving this

```bash
python3 pipelines/payload_kind_audit.py \
  outputs/raw/2026-08-17/agentic-coding-trajectory-factory

python3 pipelines/payload_kind_audit.py \
  outputs/raw/2026-08-17/agentic-coding-trajectory-factory \
  --expect docs/agentic-coding-payload-kind.json
```

The first prints the audit of every JSONL currently in the corpus. The second
re-derives the exact file snapshot named by the committed audit and exits
non-zero naming each field that has drifted from it; later append-only rounds
outside that named release snapshot do not make the historical release audit
stale. `--markdown` prints the per-record table above. The command is read-only:
it opens the corpus for reading and writes only to stdout.

`tests/test_payload_kind_audit.py` pins the same finding two ways. Its offline
class runs against a committed fixture and against the committed audit itself,
so the numbers in this document are checked in any checkout. Its raw-corpus
class re-derives the audit's named file snapshot from
`outputs/raw/2026-08-17/agentic-coding-trajectory-factory` and skips where that
gitignored tree is absent. The source directory is append-only and may contain
newer rounds that were not part of the published Hub revision.

## Scope

- No raw JSONL was modified. The corpus is opened for reading only.
- Nothing was uploaded to the Hugging Face Hub. Publishing the card text above
  is an operator action, so #74 cannot be closed by a repository change alone.
- `config/card-schemas/` is deliberately untouched. That mechanism belongs to
  the Grok 4.6 publisher (`scripts/publish_grok46_hub.py`), which does not
  manage this Fable-5 dataset; a declaration file for it would be orphaned.
