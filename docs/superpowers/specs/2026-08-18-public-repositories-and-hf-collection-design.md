# Public Repositories and Hugging Face Collection Design

Date: 2026-08-18
Status: approved; public raw release in progress, with training-readiness curation still gated
Coordinator: Codex (GPT-5.6-Sol(max))

## Objective

Publish the Synthetic Data Factory's software and project tracking in one
public GitHub repository, and create five purpose-specific public Hugging Face
dataset repositories grouped in one public collection. Public raw records are
permitted only when their provenance, intended use, and non-training-ready
status are unmistakable; the release must never describe the corpus as
curated or training-ready before curation gates pass.

## 2026-08-18 approved release amendment

This amendment supersedes the original documentation-only publication boundary
where it differs from the executed public release.

- The five public Hugging Face repositories may carry their immutable raw
  payloads and a lossless viewer projection. They remain **raw evidence**, not
  approved training data.
- The source `rmems/synthetic-factory` GitHub repository is the authority for
  tests, curation code, release metadata, and CI. Hugging Face dataset
  repositories do not execute GitHub Actions, so a central GitHub Action
  verifies their public cards, provenance, license, and viewer projection.
- Apache License 2.0 is explicitly authorized for each public dataset
  repository. Each card declares `license: apache-2.0` and each repository
  contains the full `LICENSE` text.
- A diagnostic cleaner run may write a fresh, date-labelled destination only.
  It must preserve `outputs/raw/2026-08-17` and must state whether remaining
  curation gates prevent promotion.
- Final training-ready publication remains blocked on the open tag-taxonomy
  and integration Beads (`sf-c5l.6` and `sf-c5l.7`) plus the strict curation
  audit. Public raw availability does not relax those gates.

## Publication boundary

The public state includes immutable raw JSONL payloads, a lossless
source-file/source-line/record-JSON viewer projection, a dataset card,
`.gitattributes` as supplied by the Hub, and a structured provenance record.
It does not include a curation-approved or training-ready trajectory release
until the corresponding curation and integration gates pass.

Every initial card must display all of the following near the top:

- `Status: public raw release; no training-ready data published`;
- `Visibility: public raw-data repository`;
- the dataset's specific purpose;
- whether it targets Spikenaut;
- the generation attribution below;
- a link to the public GitHub factory repository once available;
- a warning that visibility is not a training-readiness claim.

Public visibility does not itself establish training readiness. Apache License
2.0 is the user-authorized reuse license for this release and must be stated
in both front matter and the repository `LICENSE` file.

## Beads as GitHub issues

Mirror all eight current Beads into GitHub issues:

- `sf-c5l` as the parent epic;
- `sf-c5l.1` through `sf-c5l.7` as child tasks.

Create the milestone `Synthetic Corpus v0.1.0 - Training Readiness`. Create
status and priority labels, then mirror the useful domain labels already held
by each Bead.

Each issue body includes:

- a stable `<!-- bead-id: ... -->` marker;
- Bead ID, type, status, priority, estimate, and assigned agent if present;
- description and acceptance criteria;
- specification path and repository link;
- parent and blocking dependencies;
- a note that local Beads remain the machine-readable planning source.

The epic contains a checklist linking all seven child issues. Child issues link
back to the epic. After issue creation, set each local Bead's `external_ref` to
its full GitHub issue URL and commit only the resulting Bead metadata changes.

## Git and multi-agent discipline

- Push only committed files; never stage parallel agents' unrelated work.
- Keep each implementation lane in a dedicated branch and worktree.
- Require each agent to leave focused commits before integration.
- Preserve the current `Main` branch during initial publication so active work
  is not silently rebased or renamed.
- Add `origin` only after verifying that it points to
  `rmems/synthetic-factory`.
- The public GitHub repository must not receive ignored raw data or untracked
  diagnostic cleaned outputs.

## Failure and recovery behavior

Creation is idempotent at the coordinator level but does not use blind
`--exist-ok` against an unknown owner or resource. Before every create, resolve
whether the target exists and whether it belongs to `rmems`.

If a multi-resource operation stops partway through:

- retain successfully created repositories and issues;
- record their URLs;
- do not delete or recreate them;
- resume only the missing steps after a fresh inventory;
- do not upload payload data as a shortcut to make an empty repository appear
  complete.

## Verification and completion criteria

The publication shell is complete only when:

1. GitHub reports `rmems/synthetic-factory` as public and its remote matches the
   local `origin`.
2. Only committed code and metadata appear in GitHub.
3. All eight GitHub issues exist exactly once and contain unique Bead markers.
4. Every local Bead has the matching GitHub URL in `external_ref`.
5. All five Hugging Face repositories are public and contain their specialized
   raw-release card, Apache-2.0 license, provenance, and viewer projection.
6. All five repositories appear once in the public collection.
7. The two Spikenaut-targeted cards are identified correctly and the other
   three are not mislabeled as Spikenaut data.
8. Every public surface includes the exact Claude Fable 5 (Ultracode), Meta
   Muse Spark 1.2, Codex (GPT-5.6-Sol(max)), and Grok Build (Grok 4.6(xhigh))
   attribution and role distinctions.
9. Every public raw payload is labeled non-training-ready, and no curated or
   training-ready release is published before strict curation approval.
10. Central GitHub CI verifies each public Hugging Face release without
    misrepresenting GitHub Actions as an executable feature of a dataset repo.

The dataset itself is not training-ready merely because these public raw
releases exist. Curated promotion remains blocked on the strict curation audit,
sampled human review, deterministic export, and per-dataset release manifests.
