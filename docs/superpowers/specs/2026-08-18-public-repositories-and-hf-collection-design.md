# Public Repositories and Hugging Face Collection Design

Date: 2026-08-18
Status: approved in conversation; pending implementation review
Coordinator: codex/gpt-5.6-sol max

## Objective

Publish the Synthetic Data Factory's software and project tracking in one
public GitHub repository, and create five purpose-specific public Hugging Face
dataset repositories grouped in one public collection. The repository shells
must make provenance, intended use, and current readiness unmistakable without
uploading uncurated records or describing the corpus as training-ready.

## Approved topology

### GitHub

Create the public code repository:

`rmems/synthetic-factory`

It contains prompts, schemas, workflows, curation pipelines, tests,
specifications, Bead metadata, release manifests, and small synthetic fixtures.
It does not contain full raw, cleaned, candidate, or curated datasets.

### Hugging Face datasets

Create these five public dataset repositories:

| Repository | Purpose | Spikenaut target |

| `rmems/neuromorphic-event-language-bridge` | Event-stream and language-view pairs for neuromorphic grounding | Yes |
| `rmems/multi-agent-ouroboros-swarm` | Multi-agent coordination, critique, conflict resolution, and densification | No |
| `rmems/failure-as-fuel-preference-cascade` | Same-context preference data for failure recovery and alignment | No |
| `rmems/agentic-coding-trajectories` | Observable coding-agent planning, tool use, and correction trajectories | No |

Local mirrors live under `/home/raulmc/rmems/hf/<repository-name>`. Existing
projects in `/home/raulmc/rmems/hf` are unrelated and remain untouched.

### Hugging Face collection

Create one public collection titled:

`Claude Fable 5 (Ultracode)`

The collection contains all five datasets. Its description states that the
underlying synthetic data was largely generated by Claude Fable 5 (Ultracode),
that the datasets have different purposes, and that only the Thalamic Relay and
Neuromorphic Event-Language datasets directly target Spikenaut.

## Publication boundary

The first public state is documentation-only. Each Hugging Face repository
contains a dataset card, `.gitattributes` as supplied by the Hub, a structured
provenance record, and a release-status record. It contains no raw or curated
trajectory payload until the corresponding curation and integration gates pass.

Every initial card must display all of the following near the top:

- `Status: pre-release; no training-ready data published`;
- `Visibility: public metadata repository`;
- the dataset's specific purpose;
- whether it targets Spikenaut;
- the generation attribution below;
- a link to the public GitHub factory repository once available;
- a warning that visibility is not a training-readiness claim.

No license metadata or license file is invented during repository creation.
Public visibility does not itself grant reuse rights. A code and dataset
licensing decision is a separate release-gate requirement before payload data
is published.

## Beads as GitHub issues

Mirror all eight current Beads into GitHub issues:

- `sf-c5l` as the parent epic;
- `sf-c5l.1` through `sf-c5l.7` as child tasks.

Create the milestone `Synthetic Corpus v0.1.0 - Training Readiness`. Create
status and priority labels, then mirror the useful domain labels already held
by each Bead.

Each issue body includes:

- a stable `<!-- bead-id: ... -->` marker;
- Bead ID, type, status, priority, estimate, and assigned agent if present;
- description and acceptance criteria;
- specification path and repository link;
- parent and blocking dependencies;
- a note that local Beads remain the machine-readable planning source.

The epic contains a checklist linking all seven child issues. Child issues link
back to the epic. After issue creation, set each local Bead's `external_ref` to
its full GitHub issue URL and commit only the resulting Bead metadata changes.

## Git and multi-agent discipline

- Push only committed files; never stage parallel agents' unrelated work.
- Keep each implementation lane in a dedicated branch and worktree.
- Require each agent to leave focused commits before integration.
- Preserve the current `Main` branch during initial publication so active work
  is not silently rebased or renamed.
- Add `origin` only after verifying that it points to
  `rmems/synthetic-factory`.
- The public GitHub repository must not receive ignored raw data or untracked
  diagnostic cleaned outputs.

## Creation sequence

1. Commit this design with the requested co-author trailers.
2. Receive user review of the committed design.
3. Write and commit a focused implementation plan.
4. Recheck GitHub and Hugging Face authentication and name availability.
5. Create the public GitHub repository and push committed history only.
6. Create labels, milestone, and eight Bead-backed GitHub issues.
7. Link dependencies and update local Bead `external_ref` values.
8. Commit and push the Bead mappings without staging other agents' files.
9. Create five public Hugging Face dataset repositories.
10. Create the five local mirrors under `/home/raulmc/rmems/hf`.
11. Publish specialized dataset cards and structured pre-release provenance.
12. Create the public `Claude Fable 5 (Ultracode)` collection and add all five
    dataset repositories in the documented order.
13. Verify public visibility, URLs, tags, cards, issue mappings, remotes, and
    attribution by fetching every resource from its public endpoint.

## Failure and recovery behavior

Creation is idempotent at the coordinator level but does not use blind
`--exist-ok` against an unknown owner or resource. Before every create, resolve
whether the target exists and whether it belongs to `rmems`.

If a multi-resource operation stops partway through:

- retain successfully created repositories and issues;
- record their URLs;
- do not delete or recreate them;
- resume only the missing steps after a fresh inventory;
- do not upload payload data as a shortcut to make an empty repository appear
  complete.

## Verification and completion criteria

The publication shell is complete only when:

1. GitHub reports `rmems/synthetic-factory` as public and its remote matches the
   local `origin`.
2. Only committed code and metadata appear in GitHub.
3. All eight GitHub issues exist exactly once and contain unique Bead markers.
4. Every local Bead has the matching GitHub URL in `external_ref`.
5. All five Hugging Face repositories are public and contain their specialized
   card, provenance, and pre-release status files.
6. All five repositories appear once in the public collection.
7. The two Spikenaut-targeted cards are identified correctly and the other
   three are not mislabeled as Spikenaut data.
8. Every public surface includes the Claude Fable 5 (Ultracode) generation
   attribution.
9. No trajectory payload is published before strict curation approval.
10. Publication commits include the requested Claude, Codex, and Grok trailers.

The dataset itself is not training-ready merely because these public shells
exist. Payload publication remains blocked on the strict curation audit,
sampled human review, license decision, deterministic export, and per-dataset
release manifests.
